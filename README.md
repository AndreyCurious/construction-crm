# Мини-CRM «Объекты и задачи»

Постановщик управляет объектами и задачами, исполнитель выполняет назначенную работу. React, TypeScript, MUI, TanStack Query и Supabase.

[Приложение](https://construction-crm-andreycurious.glowingcricket.chatgpt.site) · [Репозиторий](https://github.com/AndreyCurious/construction-crm)

Для проверки доступны постановщик и два исполнителя. Пароли передаются отдельно; в репозитории их нет.

## Запуск

Нужен Node.js 22.12+. Заполните `.env.local` по [инструкции Supabase](docs/supabase-setup.md). Для запуска без базы используйте деморежим ниже.

```sh
npm ci
npm run dev
```

Адрес: `http://127.0.0.1:5173`. На Windows можно запустить `start-local.cmd`; в PowerShell вместо `npm` использовать `npm.cmd`.

## Проверки

```sh
npm run check
```

Запускает TypeScript, ESLint, Prettier, тесты и сборку. `npm test` отдельно проверяет логику приложения, адаптеры API и SQL-правила в PGlite. Проверки интерфейса описаны в [сценарии приёмки](docs/acceptance.md).

## Где что находится

| Каталог               | Ответственность                                |
| --------------------- | ---------------------------------------------- |
| `src/app`             | Запуск, провайдеры, маршрутизация, тема        |
| `src/views`           | Страницы и подготовка данных для них           |
| `src/features`        | Формы объектов и задач, смена статуса          |
| `src/entities`        | Сессия, запросы сущностей, их компоненты       |
| `src/widgets`         | Каркас, список задач, история                  |
| `src/shared`          | Общие компоненты, типы, функции и адаптеры API |
| `supabase/migrations` | Схема, права доступа, RPC и триггеры           |
| `supabase/tests`      | Проверки правил базы по сценариям              |
| `scripts`             | Заполнение базы и релизная сборка              |

Компоненты лежат в `ui`, хуки и типы — в `model`, стили — рядом в CSS Modules. `index.ts` содержит только экспорты. Тесты фронтенд-логики расположены рядом с кодом.

UI обращается к контракту `CrmApi` в `shared/api`. Его реализуют адаптеры Supabase и деморежима. Чтение в Supabase ограничивает RLS, запись проходит через RPC с проверками пользователя и статуса. Новую операцию нужно добавить в контракт и оба адаптера; проверки прав — в SQL.

## Деморежим

Для работы без сервера задайте `VITE_DATA_SOURCE=demo` в `.env.local` и перезапустите Vite. Кнопки входа заполняют тестовые аккаунты. Изменения хранятся в localStorage; для сброса удалите ключ `construction-crm-demo-v1`.

Это локальная демонстрация без серверной защиты. Для возврата к базе задайте `VITE_DATA_SOURCE=supabase`.

## Публикация

Приложение размещено в Sites; настройки проекта — `.openai/hosting.json`. Команда сборки — `npm run build:release`, результат — `dist`. Нужны `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`: сборка проверяет публичный ключ и включает Supabase. Для другого хостинга предусмотрены `vercel.json` и `public/_redirects`.

Административные ключи и файлы доступов не передаются на хостинг. При смене домена обновите `auth.site_url` в настройках Supabase.
