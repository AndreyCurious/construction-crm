# Решения и ограничения

## Удаление — наше решение

В ТЗ не определено, что делать с задачами при удалении объекта. Мы выбрали логическое удаление: запись исчезает из рабочих списков, а данные и история сохраняются. Объект с неудалёнными задачами удалить нельзя, даже если все они приняты. Сначала нужно перенести или удалить задачи.

Так удаление объекта не уничтожает работу и историю одним действием. Экран архива и восстановления не входит в текущую версию. При выборе сопоставлены [архивирование Jira](https://confluence.atlassian.com/adminjiraserver/archiving-a-project-938847621.html) и [работа с проектами Asana](https://help.asana.com/s/article/understanding-projects?language=en-US); запрет удаления непустого объекта — наше правило.

## Остальные решения

| Вопрос                  | Принятое поведение                                                                      |
| ----------------------- | --------------------------------------------------------------------------------------- |
| Несколько постановщиков | Управляют общей базой, авторство задачи не ограничивает редактирование                  |
| Совмещение ролей        | У аккаунта одна роль; назначать задачи можно только исполнителям                        |
| Переназначение          | Статус сохраняется. Прежний исполнитель теряет доступ, новый получает задачу с историей |
| Начало истории          | Создание задачи — первая запись. Имя автора сохраняется на момент действия              |
| Изменение полей         | История описания, адреса и переназначений не ведётся: ТЗ требует историю статусов       |
| Принятая задача         | Повторное открытие не предусмотрено заданным циклом                                     |
| Одновременное изменение | Старая версия отклоняется, чужие изменения не перезаписываются                          |

Для конфликта версий используется `PT409` → HTTP 409. `40001` может вызвать [повторные транзакции PostgREST](https://supabase.com/kb/troubleshooting/high-cpu-and-infinite-transaction-retries-when-using-custom-error-codes-in-rpc-functions).

Деморежим хранит отдельные фиктивные данные в браузере. Автоматического переноса этих данных в Supabase нет.
